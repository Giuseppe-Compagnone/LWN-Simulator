# Simulation und Nachrichten

Legen Sie vor diesen Befehlen `SERVER` und `BASE` wie unter [Verbindung und erste Anfrage](/api) beschrieben fest.

Die Pfade sind relativ zu `$BASE`. Pro Backend ist über alle Profile und Clients hinweg nur eine laufende oder pausierte Simulation erlaubt. Mindestens ein aktives Gerät ist erforderlich. Mit Bridge oder Real-Gateway Geschwindigkeit `1` verwenden. Für eine externe Bridge muss `gatewayBridge` im Startinhalt enthalten sein; die gespeicherte Konfiguration allein ersetzt diesen Parameter bei HTTP-Clients nicht.

| Methode | Pfad | Anfrage / Ergebnis |
| --- | --- | --- |
| POST | `/simulation/start` | Start: `{"speed":1,"seed":42,"gatewayBridge":{"enabled":true,"address":"127.0.0.1","port":17800}}` → Snapshot. Für rein interne Läufe `gatewayBridge` weglassen; `seed` ist optional. |
| POST | `/simulation/speed` | `{"speed":2}` → Snapshot; externe Transporte benötigen `1`. |
| POST | `/simulation/pause` | Pausieren → Snapshot. |
| POST | `/simulation/resume` | Fortsetzen → Snapshot. |
| POST | `/simulation/stop` | Stoppen → Snapshot. |
| GET | `/simulation/snapshot` | `{state,metrics,devices,gateways}` lesen. |
| POST | `/simulation/uplinks` | `{"deviceID":"DEVICE_UUID"}` → `202 {id}`. Nutzt konfigurierte Nutzdaten und Protokoll; OTAA führt gegebenenfalls zuerst einen Join durch. |
| POST | `/simulation/downlinks` | Base64-Bytes und optionale LoRaWAN-Flags → `202 {id}`. |
| POST | `/simulation/mac-commands` | `{"deviceID":"DEVICE_UUID","command":{"type":"dev-status-req"}}` → `202 {id}`. |
| GET | `/simulation/metrics` | Prometheus-Metriken als Text, nicht JSON. |


## Simulation steuern

`GET /api/simulation/activity` ist global: vor dem Start prüfen, ob eine andere Profilsimulation aktiv ist. Steueraufrufe und Snapshots liefern den Simulationszustand, keine Zustellbestätigung.

```bash
curl -fsS "$SERVER/api/simulation/activity"
curl -fsS "$BASE/simulation/start" -H 'Content-Type: application/json' -d '{"speed":1,"seed":42}'
curl -fsS "$BASE/simulation/snapshot"
curl -fsS -X POST "$BASE/simulation/pause"
curl -fsS -X POST "$BASE/simulation/resume"
curl -fsS -X POST "$BASE/simulation/stop"
```


## Nachrichten senden

Nachrichten können während einer laufenden oder pausierten Simulation eingereiht werden; bei Pause erfolgt die Verarbeitung nach dem Fortsetzen. Ein manueller Uplink kann bei einer bereits laufenden Protokolltransaktion abgelehnt werden. Die folgenden Beispiele benötigen einen aktiven Lauf: nach dem vorherigen Stopp-Befehl erneut starten.

Der HTTP-Downlink-`payload` ist immer Base64, auch bei UTF-8-Daten. `fPort` liegt für LoRaWAN-Anwendungsdaten zwischen 1 und 223; für automatische Auswahl `dataRate` weglassen. Optionale Flags: `confirmed`, `ack`, `fPending`; `macCommands` kann mehrere MAC-Befehle enthalten. Zustellung hängt von Klasse, Sitzung, Reichweite und RX-Fenstern ab. Für Raw LoRa zuerst das Gerät entsprechend konfigurieren und Raw-Bytes nicht als LoRaWAN-Anwendungsdaten verpacken.

```bash
curl -fsS "$BASE/simulation/uplinks" -H 'Content-Type: application/json' \
  -d '{"deviceID":"DEVICE_UUID"}'
curl -fsS "$BASE/simulation/downlinks" -H 'Content-Type: application/json' \
  -d '{"deviceID":"DEVICE_UUID","payload":"SGVsbG8=","fPort":10}'
curl -fsS "$BASE/simulation/mac-commands" -H 'Content-Type: application/json' \
  -d '{"deviceID":"DEVICE_UUID","command":{"type":"dev-status-req"}}'
```


## MAC-Befehle

Die Tabelle enthält MAC-Befehle und Parameter. Geben Sie die für den Befehl erforderlichen Felder an; regionale Grenzen gelten weiterhin. Frequenzen in Hz, `delaySeconds` in Sekunden und `deviceTimeMilliseconds` als Unix-Millisekunden. Nicht alle optionalen Parameter gehören zu jedem Befehl.

| `command.type` | Anfrage / Ergebnis |
| --- | --- |
| `link-check-ans` | `margin`, `gatewayCount` |
| `link-adr-req` | `dataRate`, `txPower`, `nbTrans`, `channelMask`, `channelMaskControl` |
| `duty-cycle-req` | `maxDutyCycleExponent` |
| `rx-param-setup-req` | `dataRate`, `frequency`, `rx1DataRateOffset` |
| `dev-status-req` | `—` |
| `new-channel-req` | `channelIndex`, `frequency`, `minimumDataRate`, `maximumDataRate` |
| `rx-timing-setup-req` | `delaySeconds` |
| `tx-param-setup-req` | `uplinkDwellTime`, `downlinkDwellTime`, `maximumEIRP` |
| `dl-channel-req` | `channelIndex`, `frequency` |
| `device-time-ans` | `deviceTimeMilliseconds` |
| `ping-slot-info-ans` | `pingSlotPeriodicity` |
| `ping-slot-channel-req` | `frequency`, `dataRate` |
| `beacon-freq-req` | `frequency` |
