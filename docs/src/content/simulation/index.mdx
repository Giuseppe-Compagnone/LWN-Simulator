# Simulation

The Simulation area is the operational workspace for running a LoRaWAN
network. It combines the simulation controls, live health indicators, a map of
the network, protocol commands, runtime sessions, and the event stream in one
screen.

## Before you start

Configure at least one active device and one active gateway in
[Hardware](/hardware). For a useful scenario, create devices in different
locations, choose the required device classes and activation modes, and make
sure their antenna ranges overlap the gateways that should receive them.

If you are testing real gateways, configure the [Gateway Bridge](../hardware/gateway-bridge)
before starting the simulation.

## Start a simulation

1. Open **Simulation** from the main navigation.
2. Set the **Speed** multiplier. `1.0x` follows normal simulated time; higher values are useful for testing long scenarios quickly.
3. Optionally enter a numeric **Seed** to make a scenario repeatable.
4. Click **Start simulation**.

The seed becomes unavailable after the run starts. This prevents the active
scenario from changing unexpectedly. The speed can be changed while the run
is active.

> **Tip:** A seed makes the random parts of a scenario repeatable. Use the
> same hardware configuration, seed, and speed when comparing two runs.

## Control the run

- **Pause** freezes simulated time while keeping the current state available.
- **Resume** continues a paused run.
- **Stop** ends the run and disconnects the live session.
- The status indicator shows whether the simulation is idle, running, paused,
  stopped, or failed.
- The `WS` indicator shows the live connection used to refresh the dashboard.

The speed control accepts values from `0.1x` to `10.0x`. Changing it affects
the simulation clock, not the configured uplink intervals or device settings.

## Understand the dashboard

### Packet success rate

Shows the percentage of uplinks that reached at least one eligible gateway.
The card also shows the number of successful uplinks and a short trend line.
The value becomes meaningful after traffic has started.

### Simulation uptime

Shows elapsed simulated time and the current clock multiplier. It is not the
amount of wall-clock time since the page was opened.

### Radio health

Shows the average SNR and RSSI reported by the radio model. These values help
identify weak links, excessive distance, and conditions likely to cause packet
loss.

### Network runtime

Shows the number of active devices and active gateways in the current
configuration. Inactive hardware is excluded from runtime traffic.

### Propagation map

The map displays device and gateway markers, together with temporary links for
recent communication events. Links are removed when they become stale or when
a new simulation starts. A link is drawn only when the device is within its
configured antenna range of the gateway.

Click a device to see its essential information and its white dashed antenna
coverage circle. Click a gateway to see its type, status, Gateway EUI, and MAC
address. Clicking elsewhere closes an open tooltip.

### Engine activity

The real-time event stream records protocol, radio, scheduler, and gateway
activity. Event names are formatted for readability, for example
`confirmed-data-up` appears as “Confirmed data up”. The empty state remains at
the bottom of the card until the first event is available.

### Runtime panels

**Live sessions** shows each device’s join state and uplink frame counter.
**Connectivity** shows each gateway’s connection state and packet counters in
the form `in / out`.

Real gateways can appear as reconnecting or disconnected when no external
packet-forwarder is sending UDP traffic. This is different from a virtual
gateway, which is managed entirely by the simulator.
