# Solución de problemas

Si el servidor no responde, comprueba la dirección, el puerto, el firewall y que el backend esté activo. Solo se permite una simulación por backend: detén la simulación de otro perfil antes de iniciar una nueva.

Para gateways Virtual, la dirección y el puerto en **Hardware → Gateway Bridge** identifican el servicio bridge externo que recibe el tráfico. Para gateways Real, el packet forwarder envía al listener UDP del backend (puerto 1700 por defecto). Son direcciones diferentes: consulta los [ejemplos de conexión](../hardware/gateway-bridge). Si los registros no se actualizan, comprueba la conexión y recarga la página.
