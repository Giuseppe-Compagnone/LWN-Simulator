# Gateway Bridge

Gateway Bridge conecta el simulador con un packet forwarder UDP externo, como ChirpStack Gateway Bridge. No es un gateway adicional ni crea comunicación entre gateways.

En su página configura **Enable the Semtech UDP Bridge**, **Gateway Bridge's address** (IPv4 o URL) y **Gateway Bridge's Port**. Guarda los ajustes antes de iniciar la simulación.

El bridge transporta el tráfico de gateways virtuales. Los gateways reales mantienen su propia dirección y puerto UDP. La configuración de aplicaciones y dispositivos de ChirpStack se realiza fuera del simulador.

## Tráfico Raw LoRa

El transporte UDP también admite bytes **Raw LoRa**. Configura **Radio
Protocol** como **Raw LoRa** y, para recibir tráfico raw, **Radio Receive
Mode** como **Raw LoRa** o **Auto**. Configura el bridge o el endpoint del
gateway **Real** de la forma habitual. Pasar por un gateway no añade cabeceras
LoRaWAN, cifrado ni un join al tráfico raw.

En **Engine activity** y **Logs** puedes consultar el payload **Raw LoRa ·
HEX** y el gateway asociado. Puedes conectar varios gateways a la vez: cada
uno debe tener su propio Gateway EUI, coincidente con el del packet forwarder.

Un payload raw recibido por UDP puede no contener ninguna dirección de
dispositivo. En ese caso se registra en el gateway receptor: unos bytes
arbitrarios no permiten identificar un dispositivo concreto ni dibujar su
enlace en el mapa. Un downlink raw externo sin dirección de destino se muestra
como trama, pero no se entrega automáticamente al dispositivo seleccionado ni
se distribuye a todos los dispositivos registrados.

**Auto** reconoce las tramas por su estructura. Una trama reconocida como
LoRaWAN sigue pasando por las comprobaciones habituales de sesión y MIC: Auto
no las desactiva. El bridge transporta bytes raw, pero eso no implica que
ChirpStack los interprete como tráfico de aplicación LoRaWAN. Comprueba por
separado el soporte de tramas raw del servicio externo.
