# Dispositivos

Un dispositivo es un nodo LoRaWAN de la red.

Configura su nombre, DevEUI, credenciales OTAA (AppEUI/JoinEUI y AppKey) o sesión ABP (DevAddr, NwkSKey y AppSKey), activación, clase A/B/C, intervalo de uplink, payload, FPort, posición y alcance.

También puedes definir data rate, potencia, frecuencia, canal, uplinks confirmados, ADR, contador de tramas y retransmisiones. Estos valores controlan la planificación, el comportamiento del protocolo y el resultado radio.

## Codec del payload

Activa **Payload Codec** cuando quieras mostrar el payload de la aplicación
como datos estructurados. Pega en el editor multilínea una función JavaScript
llamada `decodeUplink`:

```js
function decodeUplink(input) {
  return {
    data: {
      temperature: input.bytes[0],
      humidity: input.bytes[1],
    },
  };
}
```

La función recibe:

| Propiedad | Significado |
| --- | --- |
| `input.bytes` | Payload de aplicación descifrado como un array de bytes. |
| `input.fPort` | Puerto de aplicación configurado para el uplink. |

Devuelve un objeto con una propiedad `data` que contenga los valores que
quieres ver en el flujo de eventos. Al guardar, el simulador comprueba la
sintaxis JavaScript y la presencia de `decodeUplink`. Durante la simulación la
función se ejecuta con un límite de tiempo; un error del codec se registra en
el evento sin detener la simulación.

Cuando la decodificación tiene éxito, el flujo de eventos y el registro de la
simulación muestran el resultado junto al evento original como datos
**Decoded**. El codec se aplica únicamente a los uplinks de aplicación,
después de descifrar el payload LoRaWAN.

<Callout type="warning" emoji="⚠️">
  Trata los scripts del codec como código de configuración. Mantenlos breves,
  deterministas y sin dependencias externas. El simulador no proporciona
  acceso a la aplicación, al sistema de archivos ni a servicios de red.
</Callout>

Usa un DevEUI distinto para cada dispositivo. Completa todos los parámetros de sesión para ABP y verifica AppEUI y AppKey para OTAA.
