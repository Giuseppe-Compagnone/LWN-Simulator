# Simulazione e messaggi

Imposta `SERVER` e `BASE` come indicato in [Connessione e prima richiesta](/api) prima di eseguire questi comandi.

I percorsi seguenti sono relativi a `$BASE`. È consentita una sola simulazione attiva o in pausa per backend, tra tutti i profili e client. Serve almeno un device attivo. Usa velocità `1` con bridge o gateway Real. Includi `gatewayBridge` nella richiesta di avvio per usare il bridge esterno: il solo salvataggio della configurazione non sostituisce questo parametro per un client HTTP.

| Metodo | Percorso | Richiesta / risultato |
| --- | --- | --- |
| POST | `/simulation/start` | Avvio: `{"speed":1,"seed":42,"gatewayBridge":{"enabled":true,"address":"127.0.0.1","port":17800}}` → snapshot. Ometti `gatewayBridge` per una simulazione interna; `seed` è opzionale. |
| POST | `/simulation/speed` | `{"speed":2}` → snapshot; i trasporti esterni richiedono `1`. |
| POST | `/simulation/pause` | Pausa → snapshot. |
| POST | `/simulation/resume` | Ripresa → snapshot. |
| POST | `/simulation/stop` | Arresto → snapshot. |
| GET | `/simulation/snapshot` | Lettura di `{state,metrics,devices,gateways}`. |
| POST | `/simulation/uplinks` | `{"deviceID":"DEVICE_UUID"}` → `202 {id}`. Usa payload e protocollo configurati; OTAA può eseguire prima la join. |
| POST | `/simulation/downlinks` | Byte Base64 e flag LoRaWAN opzionali → `202 {id}`. |
| POST | `/simulation/mac-commands` | `{"deviceID":"DEVICE_UUID","command":{"type":"dev-status-req"}}` → `202 {id}`. |
| GET | `/simulation/metrics` | Metriche Prometheus in testo, non JSON. |


## Controllare una simulazione

`GET /api/simulation/activity` è globale: consultalo prima di avviare una simulazione per sapere se è già attiva su un altro profilo. Controlli e snapshot restituiscono lo stato della simulazione, non una conferma di consegna.

```bash
curl -fsS "$SERVER/api/simulation/activity"
curl -fsS "$BASE/simulation/start" -H 'Content-Type: application/json' -d '{"speed":1,"seed":42}'
curl -fsS "$BASE/simulation/snapshot"
curl -fsS -X POST "$BASE/simulation/pause"
curl -fsS -X POST "$BASE/simulation/resume"
curl -fsS -X POST "$BASE/simulation/stop"
```


## Inviare messaggi

Accoda il traffico durante una simulazione in esecuzione o in pausa; quello accodato in pausa viene elaborato alla ripresa. Un uplink manuale può essere rifiutato se il device ha già una transazione di protocollo in corso. Gli esempi seguenti richiedono una run attiva: riavviala se hai usato il comando di arresto precedente.

Il `payload` dei downlink HTTP è sempre Base64, anche se i dati sono UTF-8. `fPort` vale 1–223 per dati applicativi LoRaWAN; ometti `dataRate` per la scelta automatica. Flag opzionali: `confirmed`, `ack`, `fPending`; `macCommands` può contenere una lista di comandi MAC. La consegna dipende da classe, sessione, copertura e finestre RX. Per Raw LoRa configura prima il dispositivo: non racchiudere i byte raw in un payload applicativo LoRaWAN.

```bash
curl -fsS "$BASE/simulation/uplinks" -H 'Content-Type: application/json' \
  -d '{"deviceID":"DEVICE_UUID"}'
curl -fsS "$BASE/simulation/downlinks" -H 'Content-Type: application/json' \
  -d '{"deviceID":"DEVICE_UUID","payload":"SGVsbG8=","fPort":10}'
curl -fsS "$BASE/simulation/mac-commands" -H 'Content-Type: application/json' \
  -d '{"deviceID":"DEVICE_UUID","command":{"type":"dev-status-req"}}'
```


## Comandi MAC

La tabella elenca nomi e parametri dei comandi MAC. Fornisci i campi richiesti dal comando; restano validi i limiti regionali. Frequenze in Hz, `delaySeconds` in secondi e `deviceTimeMilliseconds` come timestamp Unix in millisecondi. Non tutti i parametri opzionali sono pertinenti a ogni comando.

| `command.type` | Richiesta / risultato |
| --- | --- |
| `link-check-ans` | `margin`, `gatewayCount` |
| `link-adr-req` | `dataRate`, `txPower`, `nbTrans`, `channelMask`, `channelMaskControl` |
| `duty-cycle-req` | `maxDutyCycleExponent` |
| `rx-param-setup-req` | `dataRate`, `frequency`, `rx1DataRateOffset` |
| `dev-status-req` | `—` |
| `new-channel-req` | `channelIndex`, `frequency`, `minimumDataRate`, `maximumDataRate` |
| `rx-timing-setup-req` | `delaySeconds` |
| `tx-param-setup-req` | `uplinkDwellTime`, `downlinkDwellTime`, `maximumEIRP` |
| `dl-channel-req` | `channelIndex`, `frequency` |
| `device-time-ans` | `deviceTimeMilliseconds` |
| `ping-slot-info-ans` | `pingSlotPeriodicity` |
| `ping-slot-channel-req` | `frequency`, `dataRate` |
| `beacon-freq-req` | `frequency` |
