# Devices

A device represents a LoRaWAN end device participating in the simulation. Its
configuration is divided into identity, activation, radio receive windows,
location, frame handling, payload generation, and advanced radio behavior.

## Identity and state

| Field | Meaning | User-visible rules |
| --- | --- | --- |
| `id` | Internal unique identifier. | Generated by the server; read-only. |
| `active` | Whether the device is enabled for use. | New devices are active by default. It can be changed while editing. |
| `name` | Friendly name shown in lists, details, and map tooltips. | Required. |
| `devEUI` | Globally unique identifier of the end device. | Required hexadecimal value with exactly 16 characters. It can be generated automatically during creation and cannot be changed during editing. |
| `class` | LoRaWAN device class. | `class-a`, `class-b`, or `class-c`. |
| `activation` | How the device obtains its session parameters. | `oota` (OTAA) or `abp`. The activation choice is fixed after creation. |

The interface displays enum values in a readable form. For example,
`confirmed-data-up` is shown as “confirmed data up”.

## Location

| Field | Meaning | Accepted value |
| --- | --- | --- |
| `latitude` | North/south position used by the map and simulation. | Decimal degrees from `-90` to `90`. |
| `longitude` | East/west position used by the map and simulation. | Decimal degrees from `-180` to `180`. |
| `altitude` | Height above sea level. | Numeric value in meters. The map can request an altitude for the selected coordinates. |
| `region` | LoRaWAN regional band plan. | `EU868`, `US915`, `CN779`, `EU433`, `AU915`, `CN470`, `AS923`, `KR920`, `IN865`, or `RU864`. |

The location fields are required. Selecting a point on the map updates the
coordinates used by the form.

## Activation credentials

Only the credential group matching the selected activation type is displayed.

### OTAA (`oota`)

| Field | Meaning | Accepted value |
| --- | --- | --- |
| `joinEUI` | Identifies the application entity that handles the join. | Required hexadecimal value with exactly 16 characters. |
| `appKey` | Secret key used to authenticate the OTAA join. | Required hexadecimal value with exactly 32 characters. |

### ABP (`abp`)

| Field | Meaning | Accepted value |
| --- | --- | --- |
| `devAddr` | 32-bit address assigned to the device. | Required hexadecimal value with exactly 8 characters. |
| `nwkSKey` | Network session key. | Required hexadecimal value with exactly 32 characters. |
| `appSKey` | Application session key. | Required hexadecimal value with exactly 32 characters. |

Changing activation mode after creation is intentionally disabled because it
changes the meaning of the session credentials.

## Receive windows

The RX1 and RX2 groups describe how the device listens for downlinks after an
uplink.

| Group | Field | Meaning | Constraint |
| --- | --- | --- | --- |
| RX1 | `delay` | Delay before opening RX1. | Integer, zero or greater. |
| RX1 | `duration` | RX1 listening duration. | Integer, zero or greater. |
| RX1 | `dataRateOffset` | Data-rate offset applied to RX1. | Integer, zero or greater. |
| RX2 | `delay` | Delay before opening RX2. | Integer, zero or greater. |
| RX2 | `duration` | RX2 listening duration. | Integer, zero or greater. |
| RX2 | `channelFrequency` | Frequency used by RX2. | Positive numeric value. |
| RX2 | `dataRate` | Data rate used by RX2. | Integer, zero or greater. |
| RX2 | `ACKTimeout` | Time allowed for an acknowledgement after a confirmed uplink. | Integer from `1000` to `3000` milliseconds. |

The contract stores the numeric values used by the simulator. Where a field is
shown without a unit in the form, use the unit expected by the selected
simulation configuration.

## Frame configuration

| Field | Meaning | Accepted value |
| --- | --- | --- |
| `fPort` | Application port used to identify the payload type. | Integer from `1` to `223`. |
| `retransmission` | Number of retries after a transmission failure. | Integer, zero or greater. |
| `FCntUp` | Uplink frame counter. | Optional; when supplied, zero or greater. |
| `FCntDown` | Downlink frame counter. | Optional; when supplied, zero or greater. |
| `disableFrameCounterValidation` | Disables frame-counter validation. | Toggle. Keep disabled unless the simulation scenario requires it. |

## Payload configuration

| Field | Meaning | Accepted value |
| --- | --- | --- |
| `uplinkInterval` | Time between consecutive uplinks. | Required positive value in seconds. |
| `oversizedPayloadBehavior` | What to do when a payload exceeds the allowed size. | `fragment` splits it into multiple transmissions; `truncate` cuts it to the maximum size. |
| `MType` | LoRaWAN uplink message type. | `confirmed-data-up` requests an acknowledgement; `unconfirmed-data-up` does not. |
| `payload` | Application data transmitted by the device. | Required text or encoded data. |
| `base64Encoded` | Whether `payload` is Base64 encoded. | Toggle. When enabled, the form validates Base64 input. |

## Advanced configuration

| Field | Meaning | Accepted value |
| --- | --- | --- |
| `antennaRange` | Maximum communication distance used by the simulation and map. | Required positive value in meters. |
| `ADREnabled` | Allows the network to optimize data rate and transmission power. | Toggle. |

When a device is selected on the map, `antennaRange` is rendered as a white
dashed coverage circle around the marker. This is a visual indication of the
configured range, not a guarantee of successful radio delivery.
