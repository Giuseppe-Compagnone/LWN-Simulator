# Simulation et messages

Définissez `SERVER` et `BASE` comme indiqué dans [Connexion et première requête](/api) avant d’exécuter ces commandes.

Les chemins sont relatifs à `$BASE`. Une seule simulation active ou en pause est autorisée par backend, tous profils et clients confondus. Il faut au moins un appareil actif. Utilisez une vitesse de `1` avec un bridge ou gateway Real. Incluez `gatewayBridge` dans la requête de démarrage pour utiliser le bridge externe : enregistrer la configuration ne remplace pas ce paramètre pour un client HTTP.

| Méthode | Chemin | Requête / résultat |
| --- | --- | --- |
| POST | `/simulation/start` | Démarrage : `{"speed":1,"seed":42,"gatewayBridge":{"enabled":true,"address":"127.0.0.1","port":17800}}` → snapshot. Omettez `gatewayBridge` pour une simulation interne ; `seed` est facultatif. |
| POST | `/simulation/speed` | `{"speed":2}` → snapshot ; les transports externes exigent `1`. |
| POST | `/simulation/pause` | Pause → snapshot. |
| POST | `/simulation/resume` | Reprise → snapshot. |
| POST | `/simulation/stop` | Arrêt → snapshot. |
| GET | `/simulation/snapshot` | Lecture de `{state,metrics,devices,gateways}`. |
| POST | `/simulation/uplinks` | `{"deviceID":"DEVICE_UUID"}` → `202 {id}`. Utilise le payload et le protocole configurés ; OTAA peut commencer par une join. |
| POST | `/simulation/downlinks` | Octets Base64 et indicateurs LoRaWAN facultatifs → `202 {id}`. |
| POST | `/simulation/mac-commands` | `{"deviceID":"DEVICE_UUID","command":{"type":"dev-status-req"}}` → `202 {id}`. |
| GET | `/simulation/metrics` | Métriques Prometheus au format texte, pas JSON. |


## Contrôler une simulation

`GET /api/simulation/activity` est global : consultez-le avant un démarrage pour savoir si un autre profil possède la simulation active. Les contrôles et snapshots indiquent l’état de simulation, pas une confirmation de livraison.

```bash
curl -fsS "$SERVER/api/simulation/activity"
curl -fsS "$BASE/simulation/start" -H 'Content-Type: application/json' -d '{"speed":1,"seed":42}'
curl -fsS "$BASE/simulation/snapshot"
curl -fsS -X POST "$BASE/simulation/pause"
curl -fsS -X POST "$BASE/simulation/resume"
curl -fsS -X POST "$BASE/simulation/stop"
```


## Envoyer des messages

Mettez le trafic en file pendant une simulation active ou en pause ; en pause, il sera traité à la reprise. Un uplink manuel peut être refusé si l’appareil a déjà une transaction en cours. Les exemples suivants nécessitent une simulation active : redémarrez-la si vous avez utilisé la commande d’arrêt précédente.

Le `payload` d’un downlink HTTP est toujours Base64, même pour du texte UTF-8. `fPort` vaut 1–223 pour les données applicatives LoRaWAN ; omettez `dataRate` pour le choix automatique. Indicateurs facultatifs : `confirmed`, `ack`, `fPending` ; `macCommands` accepte une liste de commandes MAC. La livraison dépend de la classe, session, couverture et fenêtres RX. Pour Raw LoRa, configurez d’abord l’appareil : n’encapsulez pas les octets raw dans un payload applicatif LoRaWAN.

```bash
curl -fsS "$BASE/simulation/uplinks" -H 'Content-Type: application/json' \
  -d '{"deviceID":"DEVICE_UUID"}'
curl -fsS "$BASE/simulation/downlinks" -H 'Content-Type: application/json' \
  -d '{"deviceID":"DEVICE_UUID","payload":"SGVsbG8=","fPort":10}'
curl -fsS "$BASE/simulation/mac-commands" -H 'Content-Type: application/json' \
  -d '{"deviceID":"DEVICE_UUID","command":{"type":"dev-status-req"}}'
```


## Commandes MAC

Le tableau liste les commandes MAC et leurs paramètres. Fournissez les champs nécessaires à chaque commande ; les limites régionales restent applicables. Fréquences en Hz, `delaySeconds` en secondes et `deviceTimeMilliseconds` en millisecondes Unix. Tous les paramètres facultatifs ne s’appliquent pas à chaque commande.

| `command.type` | Requête / résultat |
| --- | --- |
| `link-check-ans` | `margin`, `gatewayCount` |
| `link-adr-req` | `dataRate`, `txPower`, `nbTrans`, `channelMask`, `channelMaskControl` |
| `duty-cycle-req` | `maxDutyCycleExponent` |
| `rx-param-setup-req` | `dataRate`, `frequency`, `rx1DataRateOffset` |
| `dev-status-req` | `—` |
| `new-channel-req` | `channelIndex`, `frequency`, `minimumDataRate`, `maximumDataRate` |
| `rx-timing-setup-req` | `delaySeconds` |
| `tx-param-setup-req` | `uplinkDwellTime`, `downlinkDwellTime`, `maximumEIRP` |
| `dl-channel-req` | `channelIndex`, `frequency` |
| `device-time-ans` | `deviceTimeMilliseconds` |
| `ping-slot-info-ans` | `pingSlotPeriodicity` |
| `ping-slot-channel-req` | `frequency`, `dataRate` |
| `beacon-freq-req` | `frequency` |
